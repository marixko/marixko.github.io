## Model selection and cross-validation

The bounds of the previous lecture are too loose to choose a model in practice.
What is really used is an empirical estimate of the risk, obtained by setting
aside part of the data. This lecture closes Part III with the standard protocol:
train/validation/test split, cross-validation, and how not to fool yourself when
tuning hyperparameters.

### Contents

- K-fold cross-validation
- Leave-one-out

### Train, validation and test split

The role of each part:

- **Train**: fits the model parameters ($$\beta$$, the weights, the tree
  structure).
- **Validation**: compares models and chooses the **hyperparameters** (the
  regularization $$\lambda$$, the tree depth, the $$k$$ of the neighbors, the
  architecture).
- **Test**: used **only once**, at the end, to report performance. As soon as
  the test set influences any decision, it stops being an honest estimate of
  $$R(\hat f)$$.

### K-fold cross-validation

When the data are scarce, holding out a fixed validation set is wasteful.
**K-fold cross-validation** partitions the training data into $$K$$ blocks of
similar size. For each block $$k$$, the model is fit on the other $$K-1$$ blocks
and the error $$\hat R_k$$ is measured on block $$k$$. The risk estimate is the
average

$$
\hat R_{\mathrm{CV}}=\frac{1}{K}\sum_{k=1}^{K}\hat R_k.
$$

Each point is used for validation exactly once and for training $$K-1$$ times.

### Leave-one-out

The extreme case $$K=n$$ is **leave-one-out** (LOO): each model is trained on
$$n-1$$ points and tested on the one left out. It is almost unbiased for
$$R(\hat f)$$, but has high variance (the $$n$$ models are nearly identical) and
costs $$n$$ fits. For linear models there is an exact shortcut via the hat
matrix:

$$
\hat R_{\mathrm{LOO}}=\frac{1}{n}\sum_{i=1}^{n}\left(\frac{y_i-\hat y_i}{1-h_{ii}}\right)^{2},
$$

which gives LOO from a **single** fit.

### Choice of K and the "1-SE" rule

$$K$$ controls a trade-off of the estimate itself: small $$K$$ uses smaller
training sets and biases $$\hat R_{\mathrm{CV}}$$ upward; large $$K$$ reduces the
bias but increases the variance and the cost. In practice $$K=5$$ or $$K=10$$
are the usual values. The **one standard error rule** chooses the simplest model
whose $$\hat R_{\mathrm{CV}}$$ is still within one standard error of the minimum,
trading a little error for parsimony.

### Nested cross-validation

If we use the **same** cross-validation to choose the hyperparameters and to
estimate performance, the estimate is optimistic, because the hyperparameters
were tuned to that set. **Nested cross-validation** separates the two tasks: an
outer loop estimates the performance, and inside each partition of the outer
loop an inner loop does the hyperparameter selection. It is the correct protocol
whenever there is hyperparameter tuning and one wants a reliable final number.

### Pitfalls

- **Data leakage**: any preprocessing that uses statistics of the whole set
  (standardization, variable selection, imputation) must be done **inside** each
  partition, otherwise information from the validation block contaminates the
  training.
- **Dependent data**: time series require block partitions that respect the
  order; grouped data (several observations of the same object, field or night)
  require the whole group to stay on one side only, otherwise the model
  "recognizes" the group instead of generalizing. In Astronomy this is
  frequent: repeat splits by object, by tile or by epoch.
